# 规则类型如何选择(普通 vs 高级)

> **模块**:规则配置 · **角色**:工程师 · **配套视频**:V2 · 00:00 起

进入规则配置时,第一个决策点就是——**这条规则用普通规则还是高级规则**?选错了,要么写得很别扭,要么直接做不出来。本篇帮你 30 秒判断。

---

## 一、一句话区分

| 类型 | 一句话定位 | 谁来配 |
| --- | --- | --- |
| **普通规则** | "测点 + 运算符 + 阈值"的组合判断,系统替你算 | 工程师(不写代码) |
| **高级规则** | 用 Python 脚本写自定义逻辑,系统帮你跑 | 工程师 / 数据开发 |

**类比理解**:
- 普通规则 = Excel 公式(简单、直观、有局限)
- 高级规则 = Python 脚本(灵活、强大、需要会写代码)

## 二、先用结论决策树

```
你的规则能用一两句话讲清"什么值 + 大于/小于 + 多少"吗?
   │
   ├─ 能 → 用【普通规则】(见 #9)
   │
   └─ 不能 → 看下面三条
              │
              ├─ 涉及循环、复杂条件分支、状态机 → 【高级规则】(见 #10)
              ├─ 需要历史数据回溯、滑窗统计 → 【高级规则】
              └─ 输出不是布尔告警,而是数值指标 → 【高级规则】
```

## 三、普通规则:适用场景

**普通规则的本质是"表达式组合"**——你只能选测点、选运算符、填阈值,然后用 `AND` / `OR` 串联。详见 #9。

### ✅ 适合普通规则的场景

1. **单点超限告警** — 轴温 > 100℃ 报警
2. **多点联合告警** — 轴温 > 100℃ AND 振动 > 5 mm/s
3. **基于工况的告警** — 负荷 > 50 MW AND 排烟温度 > 600℃
4. **多测点任一异常** — A/B/C 任一温度 > 110℃

### ❌ 普通规则做不到的事

- ❌ 计算"过去 5 分钟内告警次数超过 3 次"
- ❌ 实现"如果 A 升高同时 B 下降则告警"这类**变化趋势**判断
- ❌ 调用第三方算法、机理模型公式
- ❌ 输出非告警的数值指标(如"健康度评分")

## 四、高级规则:适用场景

**高级规则用 Python 脚本编写**,你能在脚本里:
- 读取多个测点的当前值和历史值
- 写循环、条件分支、自定义函数
- 调用 NumPy / SciPy 等科学计算库
- 输出告警或自定义数值指标

### ✅ 适合高级规则的场景

1. **机理模型告警** — 用专家公式计算"热效率",低于阈值时告警
2. **复杂趋势判断** — A 上升的同时 B 必须同步上升,差异超 20% 告警
3. **滑窗统计** — 过去 10 分钟内振动峰值超 X 次告警
4. **多测点联动状态机** — 模拟启停逻辑,只在特定阶段告警
5. **输出健康度指标** — 不直接告警,而是输出 0~100 的健康分数,供「规则监测」展示(见 #21)

> 💡 **手册术语对照**:在「规则监测」页面提到的"**高级规则的指标监测**",指的就是高级规则输出的**数值型指标曲线**(详见 #21)。

## 五、对比速查表

| 维度 | 普通规则 | 高级规则 |
| --- | --- | --- |
| 配置方式 | 图形化表单(选测点 + 填阈值) | Python 脚本 |
| 学习成本 | 低(0~1 小时上手) | 中高(需具备 Python 基础) |
| 调试方式 | 用"规则图表"预览历史告警 | 脚本编辑器内联调试 + 历史回放 |
| 输出类型 | 仅告警(布尔) | 告警 + 数值指标 |
| 引用计算测点 | 支持 | 支持 |
| 引用全局触发器 | 支持 | 支持(可在脚本中显式调用,见 #15) |
| 版本管理 | 自动版本号、锁定 | 同左 |
| 修改是否需重启 | 不需要,在线热更新 | 同左 |
| 性能开销 | 低 | 取决于脚本复杂度 |
| 上线流程 | 创建 → 预览 → 启用 | 创建 → 编写脚本 → 校验 → 预览 → 启用 |

## 六、选型实操建议

**优先用普通规则**——同样的需求,能用普通规则做就别动用高级规则:
- 可视化配置便于运维同事接手
- 出问题时排查更容易
- 不依赖懂代码的人维护

**只有以下情况才升级到高级规则**:
- 普通规则反复堆 5~6 条以上仍表达不清楚
- 需要"过去 N 分钟统计"这类时间窗口计算
- 需要输出非告警的指标用于看板展示
- 业务方提供了专家公式

## 七、混用策略

**普通规则 + 高级规则 + 模型**可以**同时部署在同一设备下**,分工如下:

| 角色 | 解决的问题 |
| --- | --- |
| **普通规则** | 硬规范、强制阈值、监管要求(如规定的安全限值) |
| **高级规则** | 业务专家给出的机理判据、复合健康指标 |
| **模型(#1~#7)** | 自动发现"专家也没意识到"的异常征兆 |

> 💡 **典型部署**:1 条普通规则覆盖硬安全线 + 2~3 条高级规则做专家级判据 + 1~2 个模型做协同异常学习。

## 八、常见疑问

**Q1:之前配了普通规则,现在想升级成高级规则,能直接转吗?**

不能直接转,需要**新建一条高级规则**,把原普通规则下线即可。两者底层数据结构不同,系统没有"一键转换"功能。

**Q2:同一个测点,普通规则和高级规则同时监控会冲突吗?**

不冲突。两条规则独立判断、独立告警,即使同时触发也会分别上报为两条告警。

**Q3:高级规则的 Python 脚本能用第三方库吗?**

需要看贵司系统部署时**安装了哪些库**。常见的 NumPy、SciPy、Pandas 通常可用,其他库可能需要联系运维确认。具体见 #10。

**Q4:我们团队没人会 Python,高级规则就用不了吗?**

确实需要会基本的 Python(变量、条件、循环、函数)。如果团队暂时没人会,**优先把所有能用普通规则的需求做完**,把无法实现的需求积累起来,统一找数据开发同事配合。
