# 产品介绍

> **文档类型**：概览
> **适用角色**：全部用户
> **阅读时长**：约 3 分钟

读完本文，您将了解燃机故障预警及诊断系统是什么、解决什么问题、由哪些模块组成，以及不同角色应从哪里入手。

---

## 这是什么系统

**清洁能源燃气机组故障预警及诊断系统**（下称"本系统"或"燃机预警诊断系统"）是一套面向燃气机组的设备健康监测与故障早期预警平台。

它的核心思路：基于神经网络和人工智能算法构建设备模型，对整个电厂机组设备和系统进行智能监控，在故障逐渐出现之前、或设备退化趋势到达临界点之前尽早发现缺陷，通知电厂人员及时调整，从而消除潜在风险、合理安排维护。

---

## 为什么需要它

传统告警依赖固定的上下限阈值——只有当测点数值越过预设红线时才报警。这种方式存在明显短板：电厂运行模式多样、操作条件复杂，固定阈值既容易漏报（异常尚未越限但趋势已恶化），也容易误报（正常工况波动触发阈值）。

本系统在多样化操作条件下对设备和生产过程进行**持续监控**，用 AI 模型学习设备"正常应该是什么样"，再用实际表现与预测的偏差来判断异常。相比传统方法，它能更早、更准地捕捉到设备的早期退化信号。

最终目标：促进操作安全、提高机组设备的可靠性与安全性，实现降本增效。

## 系统由哪些模块组成

本系统主要包含以下模块：

| 模块 | 作用 |
| --- | --- |
| 全局总览 | 集团级大屏，展示平台总览、区域总览 |
| 电厂总览 | 电厂级大屏，展示系统总览、智能监盘（含 3D 主机运行状态） |
| 建模平台 | 配置模型、规则、计算测点、触发器，是分析能力的来源 |
| 趋势预警 | 实时监测模型与规则、管理告警，是日常监盘的核心 |
| 故障诊断 | 告警诊断、告警单管理、工作流处理 |
| 知识库 | FMEA 库与案例库，为诊断提供故障原因和处理建议 |
| 统计报表 | 模型、告警、告警单、案例等多维度统计分析 |
| 流程图服务 | 配置告警处理的工作流程图 |
| 数据中心 | 数据接入与管理 |
| 公共设置 | 用户、权限、角色、系统参数等管理 |

## 核心工作链路

本系统的数据流可以概括为一条主线：

**测点数据 → 模型 / 规则分析 → 产生告警 → 诊断处理 → 知识沉淀**

- 模型和规则的输入都是测点数据（原始测点 + 计算测点）。
- 模型和规则的输出都是告警：模型看"实际值与预测值的偏差是否超阈值"，规则看"测点数据是否满足预设表达式"。
- 告警产生后进入告警管理，经诊断、归档、生成告警单等流程处理。
- 处理经验沉淀到知识库，反过来提升后续诊断的准确性。

## 不同角色从哪里入手

- **电厂运行人员**：从「趋势预警」的模型监测和规则监测入手，掌握日常监盘和告警处理。
- **检修 / 工程师**：从「建模平台」入手，学习模型、规则、计算测点和触发器的配置。
- **系统管理员**：从「公共设置」入手，配置用户、角色和权限。

> 📌 使用本系统需要具备火力发电专业背景，熟悉机组日常运行、设备维护和缺陷处理的相关知识。
